# ToolAgent

基于 Function Calling 的任务型 AI 助手：把「用户自然语言 → 工具调用 → 结果汇总」做成一条可复用、可测试、异常可降级的链路。

零第三方依赖（纯 Python 标准库），**没有 API Key 也能跑通**。

## 它解决什么问题

让模型自己去查实时数据、算数字，而不是编造。难点不在"调一次接口"，而在三件事：

1. **工具怎么被模型正确选中** —— 工具的 name / description / 参数 Schema 要写清楚，否则模型乱调。
2. **模型传错参数怎么办** —— 缺参、类型错、枚举越界，必须在进业务函数之前挡住。
3. **工具挂了对话还能不能继续** —— 异常要转成结构化结果回灌给模型，让它自己决定重试还是解释。

## 架构

```
用户输入
   │
   ▼
┌─────────────┐   tools(JSON Schema)   ┌──────────────┐
│   Agent     │ ─────────────────────► │     LLM      │
│  (主循环)    │ ◄───────────────────── │ DeepSeek/Mock│
└─────┬───────┘   tool_calls           └──────────────┘
      │ execute(name, args)
      ▼
┌─────────────┐   校验失败 → 错误回灌
│ ToolRegistry│ ──────────────────────┐
│  参数校验    │                       │
└─────┬───────┘                       │
      ▼                               │
┌─────────────┐   业务异常 → 结构化错误 │
│    Tools    │ ──────────────────────┘
│ 天气/换算/订单│
└─────────────┘
```

| 模块 | 职责 |
|---|---|
| `toolagent/registry.py` | 工具注册、JSON Schema 子集校验、异常降级为结构化结果 |
| `toolagent/tools.py` | 4 个示例工具：天气、单位换算、订单查询、库存 |
| `toolagent/llm.py` | DeepSeek 客户端（含重试退避）+ 离线规则模拟器 |
| `toolagent/agent.py` | 多轮循环、`max_steps` 熔断、trace 记录、模型不可用降级 |

## 快速开始

```bash
# 离线模式（无需 Key）
python main.py

# 接入真实 DeepSeek
export DEEPSEEK_API_KEY=sk-xxx     # Windows: set DEEPSEEK_API_KEY=sk-xxx
python main.py --live

# 单条提问
python main.py --ask "120 公里换算成英里是多少"
```

运行效果（离线模式）：

```
[模式] 离线（规则模拟器，设 DEEPSEEK_API_KEY 可切换真实模型）
[工具] 已注册 4 个：get_weather, convert_unit, query_order, get_stock

[1] 用户：长春今天天气怎么样？
    助手：长春当前多云，气温 6℃，湿度 48%，西南风 3 级。
```

## 测试

```bash
python -m unittest discover -s tests -t . -v
```

19 个用例全部通过，覆盖：

- 工具描述导出格式（OpenAI / DeepSeek 兼容）
- 必填参数缺失、类型错误、枚举越界
- 字符串数字的容错转换（`"42"` → `42`）
- 未知工具、非法 JSON
- 业务异常与未预期异常统一降级
- 路由正确性、多轮上下文累积、`reset()`
- **模型不可用时整体降级不崩溃**

## 设计取舍（面试常问）

| 问题 | 选择 | 原因 |
|---|---|---|
| 为什么自己写 Schema 校验？ | 只实现用到的子集（required / type / enum） | 不引第三方依赖，逻辑透明，方便断言 |
| 工具异常为什么不直接抛出？ | 转成 `{"ok": false, "error": ...}` 回灌 | 让模型有机会换参数重试或向用户解释 |
| 为什么要 `max_steps`？ | 最多 6 步 | 防止模型在工具间死循环，也防止 token 爆掉 |
| 为什么要有 Mock LLM？ | 无 Key 也能验证链路 | 单元测试不依赖网络，CI 可稳定复现 |

## 真实边界

- 天气与订单是**本地示例数据源**，用于让链路可离线复现；对接真实 API 只需替换 `tools.py` 里两个函数的内部实现，注册与调用方式不变。
- 离线模式下的"模型"是规则路由，**不是真模型**；它验证的是工程链路，不是模型能力。设置 `DEEPSEEK_API_KEY` 后走真实 Function Calling。
